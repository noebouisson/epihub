# EpiHub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construire EpiHub, une app de bureau Electron + React qui regroupe GitHub, l'intranet Epitech, My Epitech et Teams, avec un tableau de bord unifié et des liens entre services.

**Architecture:** Le processus principal porte quatre modules de service. Chacun a la même interface (`status`/`refresh`/`cached`) et une fonction `fetch` injectée, ce qui permet de les tester sans réseau. Des modules purs gèrent les liens entre services (association repo, alertes, recherche, notifications, partage). Le renderer React affiche l'accueil, Ctrl+K, les réglages et une `<webview>` par service, chacune dans sa partition `persist:<id>`. Le processus principal réutilise ces mêmes partitions pour ses appels réseau.

**Tech Stack:** Electron 33, electron-vite 2, React 18, TypeScript 5, Vitest 2, electron-builder 25, fuse.js 7 (recherche floue).

**Spec:** `docs/superpowers/specs/2026-10-24-epihub-design.md`

## Global Constraints

- Rafraîchissement automatique toutes les **5 minutes** ; un service en erreur ne bloque pas les autres.
- Partitions de session : `persist:github`, `persist:intra`, `persist:myepitech`, `persist:teams`.
- Alerte de rendu : fin dans **< 48 h** ET (pas de repo lié OU aucun commit depuis **24 h**) ; niveau `urgent` si fin dans **< 6 h** ; une notification par rendu et par niveau.
- Mémoire de déduplication des notifications : **7 jours**.
- Renderer : `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Les webviews n'ont pas accès à Node, seule celle de Teams reçoit un preload minimal.
- Token GitHub chiffré avec `safeStorage`. Si le chiffrement n'est pas disponible, refus de stocker le token et message à l'utilisateur.
- Aucun token ni cookie dans les logs.
- Textes de l'interface en français. Thème sombre par défaut.
- Toute la logique d'URL et de décodage d'un service vit dans son seul fichier de service.

## Review Focus

1. **Dates intranet au format local** `"24/10/2026, 23:42"` : elles doivent être lues dans le fuseau local, pas en UTC, et ne pas donner `NaN` (test dans la tâche 6).
2. **Session intranet expirée** : l'intranet répond 200 avec une page HTML de connexion. L'app doit passer en `needs-login`, sans planter sur `JSON.parse` (test dans la tâche 6).
3. **Token GitHub révoqué (401)** : passage en `needs-login`, et les dernières données en cache restent disponibles (test dans la tâche 5).
4. **Titre Teams inhabituel** : `"(99+) Chat | Microsoft Teams"` donne 99, et un titre sans nombre donne 0, pas `NaN` (test dans la tâche 7).
5. **Rendus passés ou sans code projet** : aucune alerte pour une date déjà dépassée. Un projet dont le lien ne contient pas de code module n'est associé à aucun repo et ne fait pas planter l'association (tests dans les tâches 2 et 3).

### Task 3: Alertes de rendu

**Files:**

**Interfaces:**
- Consumes: `Deadline`, `Repo`, `Commit`, `AlertLevel`, `DeadlineView` (tâche 1), `matchRepo` (tâche 2)
- Produces:
  - `alertLevel(end: Date, lastCommit: Commit | null, hasRepo: boolean, now: Date): AlertLevel | null`
  - `buildDeadlineViews(deadlines: Deadline[], repos: Repo[], commits: Record<string /* repo fullName */, Commit | null>, manual: Record<string, string>, now: Date): DeadlineView[]` : exclut les rendus déjà passés et trie par `end` croissant.
  - `alertKey(v: DeadlineView): string | null` : renvoie `` `intra:deadline:${v.id}:${v.alert}` ``, ou `null` s'il n'y a pas d'alerte.

Règle : `ms = end - now`. Si `ms <= 0` ou `ms >= 48h`, pas d'alerte. Sinon, l'alerte est levée si `!hasRepo` ou si le dernier commit est absent ou date de plus de 24 h avant `now`. Le niveau est `urgent` si `ms < 6h`, sinon `warning`.

```ts
export type FetchLike = (url: string, init?: { headers?: Record<string, string> }) => Promise<{ status: number; ok: boolean; headers: { get(n: string): string | null }; text(): Promise<string> }>;
export class NeedsLoginError extends Error {}
export interface Service<K extends ServiceId> { id: K; refresh(): Promise<ServiceDataMap[K]>; }
```

- Produces (`github.ts`) : `createGithubService(fetch: FetchLike, getToken: () => string | null): Service<'github'> & { lastCommit(fullName: string, branch: string): Promise<Commit | null> }`

Appels, tous avec `Authorization: Bearer <token>`, `Accept: application/vnd.github+json` et `X-GitHub-Api-Version: 2022-11-28` :
- `GET https://api.github.com/user` → `login`
- `GET /notifications?per_page=50` → `GhNotification` (`id`, `subject.title`, `repository.full_name`, `subject.type`, URL web dérivée de `subject.url` : `api.github.com/repos/X/pulls/N` → `github.com/X/pull/N`, `issues/N` → `issues/N`, sinon `repository.html_url`)
- `GET /search/issues?q=is:open+is:pr+review-requested:@me&per_page=30` → `reviewRequests` (`kind: 'pr'`, repo tiré de `repository_url`)
- `GET /search/issues?q=is:open+is:issue+assignee:@me&per_page=30` → `assignedIssues`
- `GET /user/repos?sort=pushed&per_page=100` → `repos`
- `lastCommit` : `GET /repos/{fullName}/commits?sha={branch}&per_page=1`. Un code 409 (repo vide) renvoie `null`.

Erreurs : pas de token ou HTTP 401 → `NeedsLoginError`. Autre code non-ok → `Error('GitHub HTTP <status>')`. ETag : le service mémorise l'`ETag` et le corps de chaque URL et envoie `If-None-Match`. Une réponse 304 réutilise le corps mémorisé.

Intranet :
- `GET https://intra.epitech.eu/user/?format=json` → `login`, `promo`, `credits`, `gpa[0].gpa`
- `GET https://intra.epitech.eu/?format=json` → `board.projets[]` (`title`, `title_link`, `timeline_end`, `id_activite`) donne les `deadlines`. `projectCode` vaut le `normalize` (tâche 2) du `title` sans les espaces. L'id est `acti-<id_activite>` et l'URL est `https://intra.epitech.eu` + `title_link`. `board.activites[]` (`title`, `timeline_start`, `timeline_end`, `title_link`) donne les `events`. `history[]` (`id`, `title` sans balises HTML, `date`) donne les `notifications`.
- Login détecté si le statut est 401/403, si le corps ne commence pas par `{`/`[` après les espaces, ou si le JSON contient `message` sans `board` ni `login`. Dans ces cas, lever `NeedsLoginError`.

My Epitech :
- Le token vient de `getToken()`. S'il est `null`, lever `NeedsLoginError`.
- `GET https://api.epitest.eu/me/<scholarYear>` avec `Authorization: Bearer <token>`. Un code 401 ou 403 lève `NeedsLoginError`.

Les résultats sont triés par `date` décroissante.
